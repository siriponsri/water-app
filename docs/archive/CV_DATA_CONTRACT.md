# Cleaning Validation Data Contract

Version: 5.1  
Status: implementation baseline

## Boundary rule

Water Test and Cleaning Validation are separate data domains.

| Domain | Operational groups | Local store | Target spreadsheet |
| --- | --- | --- | --- |
| Water Test | PW/PRW, WFI/PUS | Existing Water stores | Existing RPP2 Water workbook |
| Cleaning Validation | Contact Plate, Rinse PW/PRW, Rinse WFI/PUS | `cv_records` | `RPP2-cv-record` |

Master/reference data may be reused read-only, but record IDs, worksheet sequences, pending-sync items, target tables, and document templates must not be shared across the two domains.

## CV record model

`records_cv` stores one row per controlled CV record. `recordId` is a stable UUID-like idempotency key generated by the client. `worksheetNo` is assigned once by Apps Script under a script lock in the format `CV-yy-nnnn`.

Important controlled fields:

- `recordStatus`: `NORMAL` or `RE_SAMPLING`
- `cvType`: `CV` or `CEHT`
- `sampleMatrix`: `CONTACT_PLATE`, `PW_PRW`, or `WFI_PUS`
- `reviewStatus`: `DRAFT`, `READY_FOR_REVIEW`, `APPROVED`, or `REJECTED`
- `overallResult`: `PASS`, `FAIL`, or `REVIEW_REQUIRED`
- `syncStatus`: `PENDING`, `SYNCED`, or `ERROR`

## CV sample model

`records_cv_samples` stores one row per point and joins to the parent through `recordId`.

Result values are stored without the old `9999` sentinel:

- `NUMERIC`: a measured numeric value
- `LESS_THAN_ONE`: displayed as `<1`
- `TNTC`: stored explicitly as TNTC
- `NOT_TESTED`: blank or non-final result

The client evaluates a simple numeric specification only when the specification begins with `<`, `<=`, `≤`, `>`, `>=`, `≥`, or `=` followed by a number. Any other specification remains `REVIEW_REQUIRED`; it is never silently interpreted.

## Idempotent sync

1. The browser saves only to IndexedDB and adds one deduplicated pending item.
2. CV pending items route only to `CV_SCRIPT_URL`.
3. Apps Script obtains a script lock.
4. The parent is upserted by `recordId`.
5. Existing child samples for that `recordId` are cleared and replaced.
6. The server returns the assigned `worksheetNo` and `syncVersion`.
7. Only successfully synced queue items are removed locally.

## Printing

`cv-contact-template.docx` is approved for `CONTACT_PLATE`. CV Rinse reuses the approved Water template families through separate CV-owned route keys and adapters: `cleaning-validation-rinse-pour` maps to `pw-prw-template.docx`, and `cleaning-validation-rinse-membrane` maps to `wfi-pus-template.docx`. The app never accepts a client template path and blocks missing, unknown, or conflicting methods.

## Deployment

1. Copy the files in `apps-script/` into the Apps Script project.
2. Confirm `TARGET_CV_ID` and run `testCvSchema()`.
3. Deploy or update the Web App.
4. Open Cleaning Validation → CV sync endpoint and save the deployed `/exec` URL.
5. Create one test Draft, sync it, and verify one parent row plus the expected sample rows.
